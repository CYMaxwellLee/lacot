### F1. R0 eval 的溫度座標：合成律判 T=1、帳本／CT／敘事檔全寫 T→0 — 四件套內部直接矛盾，且已寫進英文 claim 段

**所在**：
- 【合】§1.3 Lemma 1(ii)(iii)＋判決句（L58-63）：「eval 讀數 $\mathbb E_{z\sim p_\theta}[\mathrm{succ}]$
  是對 $m$ 邊際化後的期望 — sum-product 語意的泛函」「argmax 計畫對應 Viterbi＝不同的
  semiring」「**我們的訓練目標與 eval 語意住 log-semiring（T=1）**」；§1.3 表 Viterbi 行
  「argmax 單計畫 — **我們不 eval 這個**」。
- 【帳本】§0 L34：「R0 是 $T\to0$ 泛函」；§6 誠實邊界 2（L224）同句。
- 【CT】§5.2 P2（L227）：「R0/成功率是 **max 型（T→0）泛函**」。
- 【敘事】§1(7)（L90-93）：「argmax／成功率是 $T\to0$ 泛函」「**內化存在 T=1、消費在 T→0**」；
  §2 claim 段英文（L121）：「consumption happens at $T\to0$ in success rate」、中文（L132）同。

**論證**（可獨立複現）：
1. R0 eval 的定義（全體系一致）＝$z\sim p_\theta(\cdot|s,g,\varnothing)$ 抽樣、decode、執行、
   取成功率 $\mathbb E_{z\sim p_\theta}[\mathrm{succ}(D(z),g)]$。這是**期望**泛函 — 對 route
   混合線性（$\sum_m w_m\,\mathbb E[\mathrm{succ}|m]$），即 $T{=}1$ 的 $\oplus$（sum）語意。
   【合】Lemma 1(ii) 的證明正是這句（「期望對混合分佈線性」），並明文把 argmax（Viterbi）
   排除在我們 eval 之外。
2. 「$T\to0$ 泛函」的字面義＝值由 $\max$／argmax 決定（tropical 端）。R0 eval 裡沒有任何
   argmax：不取最大機率計畫、不做 max over routes。兩個陳述不能同真 — 這不是措辭差，
   是同一個數學對象被釘在溫度族兩端。
3. 下游想抓的直覺是對的、標籤是錯的：「oracle 的 route-diversity bits 定價在 NLL、不定價
   在 R0（argmax route 可產即滿分）」（CT P2 原句）— 真正的機制是 **succ 對 route 標籤的
   不變性**：成功率只依賴「抽到的計畫是否合法達標」、對質量在等價 route 間怎麼重分佈
   不敏感（sharpening 塌到單一合法 route ⇒ NLL 變差、R0 不動 — 解耦例）。這是「泛函對
   某子 σ-代數的不變性」，不是 $T\to0$。$T\to0$ 的合法住戶是：BFS（凍結極限、Lemma 2）
   與 refine/BoN 的**部署極限方向**（【合】R2 且自標「我們部署點在溫度族中段」）。
4. 後果：P2 的可測預測（NLL-gap 與 R0-gap 解耦、R0-gap 先閉）**本身不倒**——但其理論
   機制解釋要重寫；「內化存在 T=1、消費在 T→0」這句已進 §2 英文 claim 段，reviewer 拿
   【合】Lemma 1 判決就能自家互戳；帳本 §0「換算屬 Lemma 1/2 管區」的引用也連帶錯位
   （Lemma 1/2 講 (CL) 值函數的溫度族、不是 NLL→R0 換算）。

**改寫建議**（三檔同步）：
- 「消費在 $T\to0$」→「消費在**支撐敏感、質量不敏感**的成功率泛函（對 route 邊際化線性、
  對等價 route 間的質量重分佈不變）；refine/BoN 把部署有效溫度往 0 壓（R2）、BFS 是
  $T\to0$ 凍結極限」。
- CT P2 的「max 型（T→0）泛函」刪掉括號、改「支撐泛函」；解耦預測的機制句改用
  「route-invariance of succ」。
- 帳本 §0/§6 的「R0 是 $T\to0$ 泛函」同改；「Lemma 1/2 管區」改為「Lemma 1 釘 eval 語意、
  C-ii′ 管 bits→變異 — R0 換算的正式橋目前**沒有**、標 open」。
- 若要保留 T→0 說法，唯一自洽路徑是「R0 eval 實際帶 value-directed refine ⇒ 有效溫度
  <1」— 但那要先查 eval code 是否帶 refine，且至多到「中段」、仍非 $T\to0$；不建議。

## 2.【重要】

### M1. 「rung 0 無 headroom ⇒ 幫浦無輸入＝定理」在 dense reward 下有反例；「一魚兩吃」同縫

**所在**：【帳本】§4 表 GRPO 行＋BoN 行（「pass@G−pass@1 gap＝這條臂的價值量測**兼**
幫浦輸入量測 — 一魚兩吃」）、§5（「rung 0 無 headroom ⇒ 幫浦無輸入…是定理不是比喻」）；
【敘事】§1(6) 同句轉引。

**論證**：L4(ii) 的定理內容＝「群內 reward 全同 ⇒ $\hat A\equiv0$ ⇒ 該群貢獻恰 0」— 對。
但 headroom 的操作定義是 pass@G−pass@1 gap，而設計卡 §2.1 的 reward 是 **dense 三項加權**
（r_legal＋r_reach＋r_hit）。反例：某群 $G$ 條全部未達標（pass@G＝pass@1＝0 ⇒ gap＝0）
但各條 r_reach 不同（末點離 goal 距離不同）⇒ 群內 reward 有變異 ⇒ $\hat A\ne0$ ⇒ 幫浦
**有**輸入（且梯度方向有意義：往離 goal 近的方向搬質量 — 這正是 dense reward 的存在
理由）。⇒ 「gap=0 ⇒ 無輸入」為偽；成立的只有逆向（reward 全同 ⇒ pass 全同 ⇒ gap=0）。
兩者等價僅當 reward 退化為 binary hit。設計卡 §4 rung 0 的 gate 寫的是對的
（「headroom 與 gap **至少一個**顯著>0」— 退化群比例與 pass gap 並列）；帳本把雙錶壓縮
成單錶再升格為「定理」。實際風險：明早 rung 0 若量到 pass gap≈0 而 reward 有變異，
按帳本句會錯砍臂（敘事檔又規定「衝突時以來源檔為準」、來源檔正是帳本）。

**改寫建議**：帳本兩處改「退化群比例＝1 ⇒ 幫浦零輸入（L4(ii) 字面義、定理）；
pass@G−pass@1 是 BoN 臂價值錶、對幫浦輸入只是**單向訊號**（gap>0 ⇒ 有輸入；gap=0 在
dense reward 下不判死、看退化群錶）」。「一魚兩吃」句補「reward 二值時兩錶重合」限定。
