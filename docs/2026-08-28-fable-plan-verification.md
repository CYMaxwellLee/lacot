## ② ⭐ X 對照那個 bug 的實例，比 Fable 說的更值得看

`[實測]` `slurm_outputs/devday-ms0.out:40-53`（medium-stitch seed 0，官方 250 題尺）：

```
  誠實 BC 地板          0.476
  u 歸零                0.292
  別人的 u              0.308
  LaCoT refine R=1（正向）  0.292
  反向 refine R=1        0.488   ← 比正向高 19.6 點，而且【追平 bc】
  ⇒ 印出來的判讀：「方向確實有影響 ⇒ refine 這條鏈是活的」
```

⇒ 🚨 把 refine **反過來跑**成績反而追平地板 ⇒ 正向 refine 是**主動有害**，
　 ⛔ 不是「沒在做事」。而判準只看差值大小、不看正負 ⇒ 印成「活的」。

⚠️ 而 seed 2 的方向是**相反**的（`devday-ms2`：正向 0.796 / 反向 0.644）
　 ⇒ 兩個 seed 方向不一致 ⇒ ⭐ 這條鏈的「活」本身就不穩定。

⇒ 這跟 `l_refine` 下毒的機制吻合：refine 被訓練成朝「head 會忽略」的方向推。
⇒ P0′ 刪掉 learned refine 之後此 bug 無關緊要（Fable 判斷正確，不用修）。

## ③ 🚨 不成立的一條 ——「訓練在主動銷毀路徑資訊」

Fable 引：未訓練 encoder `r2_L=0.507` → 訓練後 `0.246` ⇒ InfoNCE 把路徑資訊往外丟。

`[實測]` 那個數字出自 `value_u_..._interp_q1_s0.json`，而 **`q` 就是 `LACOT_SG_QUERY`**
（`exp_value_u.py:827` 的檔名模板、`:74` 的旋鈕）⇒ **q1 的 encoder 把 (s,g) 當 query token 餵進去**。

⇒ ⛔ 而主線 `scratch_lacot_rollout.py:185` 的 `etarget(traj, mask)` **完全不吃 (s,g)** ⇒ 主線是 **q0**。

```
                              r2_sg      r2_L
q1（Fable 引的，非主線架構）
  沒訓練                      0.99998    0.507     ← (s,g) 直接餵進去 ⇒ 白送的
  訓練過                      0.9988     0.246
q0（主線的架構）
  沒訓練                      0.5918    -3.31      ← 負的＝比預測平均值還爛
  訓練過                      0.9203     0.145     ← ⭐ 方向是【拉上來】，不是丟掉
```

⇒ 🚨 **在主線架構上方向相反。** q1 那個「下降」是白送的 (s,g) 線性可讀性散掉，
　 ⛔ 不是路徑資訊被銷毀 —— 而 Fable 自己的門票設計裡就寫了要算 partial r2（扣掉 (s,g)），
　 ⭐ 只是引這條證據時沒扣。

⚠️ **我 8/27 也用錯了同一批**：交接 ④ 寫「乾淨支持論點的是同批新版的兩個（q0 與 q1）」——
　 我糾正了 Fable 引舊版檔案，⛔ 卻沒發現我引的 q1 是不同架構。
　 ⇒ ⭐ 同一族結果檔的辨識旋鈕藏在檔名尾巴兩個字元裡，這已經是**第三次**咬到我們。

⇒ **對 P0 的影響**：換 encoder 目標**仍然值得做**，⛔ 但理由要換成站得住的那條 ——
　 拿 128 個座標點直接算相鄰距離加總，路長排序準確率就有 0.973（算術給的，不是學的）；
　 且 V_geo 無論如何需要那顆 decoder。
　 ⛔ 「訓練在主動銷毀資訊」不准寫進 design doc 或論文。

## ④ 🚨 我額外抓到的：特異度 gate 是恆過的

`[實測]` `bc` 與 `bc_rerun` 在**全部 5 個結果檔裡位元相同**（連 `best_dist_med` 到小數點後 15 位）。

`scratch_lacot_rollout.py:407` 的 `bc_rerun` 只換 `torch.manual_seed`，而 rollout 是確定性的
⇒ 換 seed 什麼都不影響 ⇒ 這個 gate 在比較「同一個東西跟它自己」。

⚠️ **講準**：這 ⛔ 不代表配對沒釘好 —— 確定性系統的配對天生就釘好。
　 它代表的是：**我們宣稱「驗過配對」而其實沒驗過**，8/26 那次「尺的驗收通過」有一半是空的。

⇒ 修法二選一（待裁）：① 讓 `bc_rerun` 真的改變某個東西（GPU 非確定性、或注入 action noise）；
　 ② 把它從 gate 降級成註記，並在引入任何非確定性 arm（例如 grad arm）時重新升回 gate。
